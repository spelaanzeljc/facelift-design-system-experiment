Guidelines

Guidelines

Prescriptive rules for building new screens or modifying existing ones. Every rule maps directly to tokens, components, or patterns found in the design system. When in doubt, check output/components/ before writing any custom markup.

Core Principles

01
Rules
Tokens First

Every colour, font, shadow, and spacing value must come from tokens.css. Never write a raw hex, rgba(), or hardcoded px value for any design property.

Components Before Custom

Before writing any UI element, search output/components/ and output/components2/ by family name. If a matching family exists, mirror its exact HTML structure and dimensions.

Semantic Tokens

Always use semantic tokens (--sys-primary-default, --sys-text-primary) over reference palette tokens (--blue-500, --grey-900). Use reference tokens only when no semantic alias exists.

State Defaults

Use the state-default variant as the base. Layer hover, focus, active, and disabled states via CSS on top — don't load separate component files per state at runtime.

Type Scale

Use the BB Update body/heading scale (Helvetica Neue) for all in-app UI. Reserve Lota Grotesque exclusively for marketing or hero sections. Never mix the two within the same UI context.

Icon Sizing

All icons are designed on a 20×20 or 24×24 grid. Default to 20px. Check the surrounding component's HTML file to confirm the intended size before placing an icon.

Rules
Sort indicator.Show ↑ or ↓ inline in the active sort column header. Only one column sorted at a time. No indicator on inactive columns.
Inline toggle.On/off state rows (e.g., enabled strategy): render a toggle switch as the first element in the name column, before the label. Blue = on, grey = off.
Inline status edit.Editable status cells show a ▼ chevron after the label. Clicking opens a popover — not a full modal.
Tag chips.Render each tag as a colored pill (appearance_colored family). Show first two then a grey +N overflow chip. Never wrap to a second line.
Assignee avatars.Stack avatar circles with negative margin overlap. Show up to 3; use a +N grey circle for overflow. No names in the cell.
Label color dot.In label/tag list tables, prefix the row name with a filled circle (~8px) in the label's own color. This is the only place a raw color value may appear — it is data, not a design decision.
Warning state.Rows with a configuration error show a warning triangle icon (amber) in place of the content icon. Do not change the row background.
Row borders.Use --sys-border-subtle horizontal dividers. No vertical column dividers. Header row uses --sys-border-soft bottom border.

Accessibility

15
Rules
Colour contrast.All text on light backgrounds must meet WCAG AA (4.5:1 for normal text, 3:1 for large text). Default pairing: --sys-text-primary on --sys-background-base.
Focus states.Every interactive element must have a visible focus ring using --sys-border-focus. Never suppress outline without a CSS-based replacement.
Icon-only buttons.Always include aria-label or a visually hidden label. Never rely on a tooltip as the only accessible label.
Disabled menu items.Use aria-disabled="true". Do not use disabled on <button> inside menus — it removes focus and prevents tooltip delivery.
Motion.Wrap non-essential transitions in @media (prefers-reduced-motion: reduce) and disable them when the user has requested reduced motion.

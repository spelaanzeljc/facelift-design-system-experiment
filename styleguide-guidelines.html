Guidelines

Guidelines

Usage principles, accessibility standards, and design decisions that govern how the system is applied.

Core Principles

Tokens First

Every colour, size, and shadow must reference a --token from tokens.css. Never write raw hex, rgba, or hardcoded pixel values for design properties.

Components Before Custom

Before writing any UI element, check output/components/ for a matching family. Only build custom if no match exists. Mirror the component's exact dimensions and markup structure.

Semantic Tokens

Always prefer semantic tokens (--sys-primary-default, --sys-text-primary) over reference palette tokens (--blue-500, --grey-900). Use reference tokens only when no semantic alias exists.

State Defaults

Use the state-default variant as the base. Layer hover, focus, active, and disabled states via CSS on top — don't load separate component files per state at runtime.

Type Scale

Use the BB Update body/heading scale (Helvetica Neue) for all in-app UI. Reserve the Lota Grotesque display scale exclusively for marketing or hero sections. Never mix the two within the same UI context.

Icon Sizing

All icons are designed on a 20×20 or 24×24 grid. Default to 20px. Check the surrounding component's HTML file to confirm the intended size before placing an icon.

Accessibility

Colour contrast: All text on light backgrounds must meet WCAG AA (4.5:1 for normal text, 3:1 for large text). Use --sys-text-primary on --sys-background-base as the default pairing.
Focus states: Every interactive element must have a visible focus ring using --sys-border-focus. Never suppress outline without a CSS-based replacement.
Icon-only buttons: Always include an aria-label or visually hidden label. Never rely on a tooltip as the only label for an action.
Motion: Respect prefers-reduced-motion. Wrap non-essential transitions and animations in a media query and disable them when the user has requested reduced motion.

Guidelines

Guidelines

Prescriptive rules for building new screens or modifying existing ones. Every rule maps directly to tokens, components, or patterns found in the design system. When in doubt, check output/components/ before writing any custom markup.

Core Principles

Tokens First

Every colour, font, shadow, and spacing value must come from tokens.css. Never write a raw hex, rgba(), or hardcoded px value for any design property.

Components Before Custom

Before writing any UI element, search output/components/ and output/components2/ by family name. If a matching family exists, mirror its exact HTML structure and dimensions.

Semantic Tokens

Always use semantic tokens (--sys-primary-default, --sys-text-primary) over reference palette tokens (--blue-500, --grey-900). Use reference tokens only when no semantic alias exists.

State Defaults

Use the state-default variant as the base. Layer hover, focus, active, and disabled states via CSS on top — don't load separate component files per state at runtime.

Type Scale

Use the BB Update body/heading scale (Helvetica Neue) for all in-app UI. Reserve Lota Grotesque exclusively for marketing or hero sections. Never mix the two within the same UI context.

Icon Sizing

All icons are designed on a 20×20 or 24×24 grid. Default to 20px. Check the surrounding component's HTML file to confirm the intended size before placing an icon.

Layout Patterns

Three layout archetypes cover all screens. Pick the one that matches the screen's information density and task flow.

Archetype Structure When to use
Standard Top nav bar + left sidebar + main content area Settings pages, dashboards, single-focus views (Frames list, Users list)
Three-panel Top nav bar + Feed panel (fixed ~300px) + Context panel (flex) + Details panel (fixed ~280px) Inbox/feed workflows where selecting an item shows both context and metadata (Engage)
Four-panel Top nav bar + Inboxes panel (fixed ~240px) + Feed + Context + Details Feed workflows that also need secondary inbox/filter navigation
Panel collapse.Every panel except the main content area must include a ◀ collapse button in its header. Collapsed state hides the panel; the icon-only sidebar remains visible.
Panel scroll.Each panel scrolls independently. Never let one panel's scroll affect another.
Detail panel open.The details panel slides in from the right and overlays the calendar/grid area. It does not push or resize adjacent panels.
Page background.Use --sys-background-neutral (#f3f5f7) as the page background for dashboard and settings layouts. Use --sys-background-base (#ffffff) for panel interiors and card surfaces.

Page Header Anatomy

Slot order — standard page header
Title rowPage title (heading-xl or heading-lg) left-aligned + optional dropdown chevron for context switching + optional ⋯ overflow menu — all left. CTA buttons right-aligned.
Subtitle / quota rowOne line of plain --sys-text-secondary text: counts, quota ("Users: 102 / 500 • Admin users: 86 / 290"), or filter summary. Sits directly below the title.
CTA buttonsSecondary ghost buttons first (leftmost) → primary filled button last (rightmost). Each button may carry a 20px icon that clarifies the action.
Split CTA.When a primary action has sub-actions, use a split button: primary label segment + a hairline divider + a separate chevron-down segment. Both share the same --sys-primary-default background. The divider is a semi-transparent white stroke.
Count display.Show the total count of listed items below the title as a plain text line (e.g., "75 labels"). Do not wrap it in a badge or chip.

Data Tables

Standard row anatomy
Col 1Optional expand chevron (▶/▼) for parent rows — only present when the row has children
Col 2 — Name16–20px colored icon + primary title (body-md-medium) stacked above secondary sub-label (body-sm-regular, --sys-text-secondary)
Col 3 — ⋯Overflow action button — appears on row hover only, hidden at rest
Data columnsPublication date (calendar icon prefix), Status (colored circle + label + inline dropdown chevron), Tags (colored pill chips + +N overflow), Assignees (stacked avatar circles)
Last columnsTimestamps, IDs — plain text, right-aligned, --sys-text-secondary
Sort indicator.Show ↑ or ↓ inline in the active sort column header label. Only one column sorted at a time. No sort indicator on inactive columns.
Inline toggle.When a row has an on/off state (e.g., enabled strategy), render a toggle switch as the first element inside the name column, before the label. Blue = on, grey = off.
Inline status edit.Status cells that are editable show a dropdown chevron (▼) directly after the status label. Clicking opens a popover — not a full modal.
Tag chips in rows.Render each tag as a colored pill (appearance_colored family). When more than 2–3 tags exist, show the first two and a grey +N overflow chip. Never wrap to a second line.
Assignee avatars.Stack avatar circles with a small negative margin overlap. Show up to 3; use a +N grey circle for overflow. No names in the cell.
Label color dot.In label/tag list tables, prefix the row name with a filled circle (~8px) in the label's assigned color. This is the only place a raw color value may appear outside of a token — it is data, not a design decision.
Warning row state.Rows with a configuration error show a warning triangle icon (amber) in place of the normal content icon. Do not change the row background.
Row borders.Use --sys-border-subtle horizontal dividers between rows. No vertical column dividers. Header row uses --sys-border-soft bottom border.

Context Menus & Dropdowns

Container.White card (--sys-background-base), rounded corners (8px), --shadows-shadow-md elevation, no internal dividers between items. Min-width 200px.
Item structure.Each item: 20px outlined icon left-aligned + 12px gap + body-md label. Never use filled icons inside menus.
Disabled items.Render disabled items in the list at their natural position — do not hide them. Set both the icon and label to --sys-text-disabled. Do not add a tooltip explaining why unless the reason is non-obvious.
Trigger.Context menus are always triggered by a ⋯ (three-dot) icon button. The button has no visible border at rest; it gains a --sys-secondary-hover background on hover.
Positioning.Open menus must render above all other content (use z-index above panels). A menu triggered inside a panel must not be clipped by the panel's overflow:hidden.

Do

Use ◆ Successful (diamond icon + label, no pill) for post status on calendar cards and in panel headers. Use the status_* component family from output/components/.

Don't

Don't use a solid pill chip for post status — that pattern is reserved for sentiment badges (Engage) and appearance chips (colored labels). Mixing the two makes status semantics ambiguous.

Empty States

Structure — all empty state contexts
Icon / illustration64px, centered horizontally. Use a muted grey icon (--sys-text-disabled) or a branded illustration. Never a color icon.
HeadingBold, heading-sm or heading-md. Directly states what's missing ("No messages yet", "There are no comments available.").
Supporting text1–2 lines, body-sm-regular, --sys-text-secondary. Explains why or what to do next.
CTA (optional)Primary or secondary button below the text. Only include when there is a direct action the user can take from this state.
Centering.Center the empty state both vertically and horizontally within its container. For tall panels, use display:flex; flex-direction:column; align-items:center; justify-content:center.
Accordion section empty state.When a collapsible sidebar section has no items, show two stacked lines inside the section body: bold "No data existing" + secondary "There are no entries". No icon needed at this small scale.
Widget card empty state.Dashboard widget cards that have no data use the same icon + heading + body pattern scaled to fit the card. No full-page empty state treatment needed.

Banner action button.The CTA inside a system banner uses the matching semantic color as its background (e.g., orange button on orange banner). It is not a standard primary blue button.

Accessibility

Colour contrast.All text on light backgrounds must meet WCAG AA (4.5:1 for normal text, 3:1 for large text). Default pairing: --sys-text-primary on --sys-background-base.
Focus states.Every interactive element must have a visible focus ring using --sys-border-focus. Never suppress outline without a CSS-based replacement.
Icon-only buttons.Always include aria-label or a visually hidden label. Never rely on a tooltip as the only accessible label for an action.
Disabled menu items.Render disabled menu items with aria-disabled="true". Do not use disabled on <button> inside menus — it removes focus and prevents tooltip/explanation delivery.
Motion.Wrap non-essential transitions and animations in @media (prefers-reduced-motion: reduce) and disable them when the user has requested reduced motion.
